- 2026-11-23 : mise a l'echelle Windows (150%) cassait tout l'onglet Jeux (textes/boutons superposes au bas de l'ecran), faussement pris au debut pour un bug de manette/focus. Cause reelle, en trois couches : (1) le manifeste dpiAware=false rendait Hearth non-adapte au DPI, donc les API Windows mentaient de facon incoherente entre elles selon celle appelee (certaines renvoient la resolution physique, d'autres une resolution << virtualisee >> par le facteur d'echelle) ; (2) build.rs n'avait pas de rerun-if-changed sur hearth.rc/hearth.manifest, donc toute correction du manifeste restait silencieusement non recompilee (piege a retenir) ; (3) une fois le manifeste reellement DPI-aware, la negociation de taille de fenetre avec winit (plein ecran natif ou taille physique explicite) restait peu fiable. Corrige : manifeste authentiquement PerMonitorV2, SLINT_SCALE_FACTOR=1 (1 pixel logique = 1 pixel physique, impose nous-memes plutot que de laisser Windows ou Slint agrandir l'image), fenetre recalee explicitement sur l'ecran via wm::fit_to_monitor (meme mecanisme deja fiable pour les jeux) plutot que de faire confiance a la negociation de taille de winit. Verifie a l'ecran (captures) a 150% : plus aucun chevauchement, fenetre pleine resolution (2560x1440) confirmee par deux lectures Fg espacees (une lecture immediatement apres Deploy peut etre perimee, avant que le recalage n'ait eu le temps de s'executer).
